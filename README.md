# StudyHelp 通用题库工坊 (test2)

上传一本教材/试卷 PDF，自动得到：（全部产物在 `output/<工作项>/`）切好的题目图、逐题解答（带独立评审）、`Book_*.md`、`Book_*.pdf`、可交互的做题网页。

## 使用

```
python main.py                       # 启动网页 http://127.0.0.1:8089，点「上传教材」即可
python main.py ingest --pdf X.pdf --type book --subject ee      # 命令行全流程
python main.py ingest --pdf X.pdf --no-solve                    # 只切题
```

网页上传后立即返回，后台依次执行：**切题 → 题干转写与逐符号核对 → 求解 → 解答检验 → 汇编 MD → 编译 PDF**，页面顶部进度条实时显示（`/api/ingest/status`）。

- **只切题，先不解题**（上传弹窗勾选）：切完题、核对完题干就停下，逐题检查切片没问题后点顶部“▶ 开始解题”（不会重切）。
- **只看待复核**（题目导航右上角）：只列出评审未达标、题干在解题后被更正、或检验有问题的题，角标显示“⚠ 复核 分数”。
- **重解本题**（解答栏右上角 / 待复核提示条）：后台重解这一题 → 检验 → 刷新合订本与 PDF；
  原题栏底部“题干识别有误？重新识别并重解”会先按原图重新识别题干。
- **本书用量**（题目导航上方）：真实 token 用量，按阶段可展开明细。
- **导入题目文本**（上传弹窗可附文件，或侧栏“📥 导入题目文本”）：点“复制提示词”，在大模型网页对话框里上传 PDF 并粘贴提示词，
  把它输出的全部题目（`### 3.12` 这样的题号标题）导入。按题号对上的题直接用这份题干（原题栏、Compact、解题都用它），
  不再看图转写和核对；没对上的题照常转写。导入后给出对账：文本里有但没切出来（切题可能漏了）、切出来了但文本里没有、题号重复。
  勾选“导入后仍逐题核对”则照常逐题对照原图核对（更稳，但不省 token）。代码见 `core/timu_import.py`。

## 切题原理（core/ocr_book_cropper.py）

1. 有文字层的 PDF 直接读文字坐标；扫描件走本地 OCR（RapidOCR），只用于**定位**，不提供题干文字。
2. **阶段A（全书）**：文字行检测 + 识别短行/大字号行，标出“习题/思考题/基本题…”标题页、章首页、答案区、目录页。
   - 页面顶部 12% 的“第N章…”视为页眉，不当作章首；含句中标点的句子（如“…并验证你的答案。”）不当作答案区标题。
3. **阶段B（仅习题区）**：逐页识别每行最左侧几个字，题号只接受“期望的下一个序号”。支持：
   - 带章号：`3.12` / `3-12` / `3－12`（题号与正文粘连也能拆开）；
   - 不带章号：`1.` / `1、` / `第1题`（章号取页眉“第N章”）；
   - 漏号补识别：缺号时在前后两题之间的题号列用 2 倍分辨率重新 OCR，找回漏掉的题号。
4. **切图**：题与题之间在“行间空白带”下刀（只看版心左侧 70%，不受右侧得分框/公式编号干扰）；
   识别脚注分隔线，脚注不进题目；跨页题自动拼接；题目下方大片空白自动去掉。
   求和号上限这类贴着本行、正对下方符号的小块墨迹归本题（不会被切进上一题）。
   **插图归位**：前一题的插图排在后面（甚至下一页顶部）时，按单独成行的图注（如“图 P3.45”）补回所属题；
   图块里只有插图就移走，两题插图并排就复制，图文左右混排就只截插图那一侧复制，分不开的记 `figure_unresolved`。
5. **整本书版式参数**：抽样习题页，按奇偶页分别用墨迹投影求正文左右边界，整本书统一使用，并与本页实际墨迹取并集（宁宽勿窄）；
   全部切片做“内容贴边”确定性检查，贴边就放宽余量重切；大模型对样例切片的意见仅作参考记录在 `crop_report.json`。
6. **扫描版试卷**：没有文字层的试卷按“一、选择题…”等大题分组，题号 `1.`、`2.` …（支持跨大题连续编号）。
   有文字层的试卷仍走旧版文字层切题器 `core/legacy_exam_cropper.py`。
7. 一道题都没识别到时，不改动已有结果。OCR 结果缓存在 `_cache/`，中断后可续跑（网页“继续构建”或 `/api/ingest/resume`）。

## 解题质量闸门（core/solver.py）

草稿（直接按定稿结构书写并附速查）→ **独立评审调用**（解析真实分数）→ 低于 95 分带评审意见重写（最多 2 次）。
- 评审 ≥95 分：草稿即定稿，不再整篇重写（slot 里 `final_mode=draft_passed`）；
- 始终未达标：带最佳草稿与评审意见重写定稿（`final_mode=rewritten`），并标注“待人工复核”。
分数无法解析记为 `unreviewed`，不再默认给 98。

省 token 的设置（`core/solver.py` 的 `THINK_BUDGET` / `MEDIA_RES`）：
- 思考预算按阶段：转写 2k、核对 4k、评审 6k、首轮草稿 8k（选择/填空/判断 4k）、重写轮与定稿 12k；
  环境变量 `STUDYHELP_THINKING_BUDGET` 设了就统一覆盖。
- 题图分辨率：转写和核对用高分辨率（要看清下标），推导/评审已有文字题干，用中分辨率（`STUDYHELP_MEDIA_RES` 可改）。

## Token 记账（core/usage.py）

每次模型调用的真实用量（输入/输出/思考）追加到 `output/<工作项>/usage_log.jsonl`（阶段、题号、时间），
每题合计另存在 slot 的 `usage` 字段；网页“本书用量”与 `/api/usage` 汇总显示。此功能上线前构建的书没有记录。

## 最终检验（core/verifier.py）

检验分两次：切完题后先做**题干**（解题直接用核对过的题干），解完后再做**解答**。结果写入 `output/<工作项>/verify_report.json`：
- 题干：先由模型按原图转写，再由另一次调用对照原题切片核对**内容**（主体、条件、数值、公式、全部小问），
  公式**逐符号比对**（q/g、l/1、o/0、v/ν、≈/= 这类形近字），不一致就按原图重新转写并写回；
  若题干在解题后才被更正，该题标记 `stale_text`，网页提示重解；
- 排版：移植 test1 的做法，用 OCR 找 (a)(b)(1)(2) 小问标号坐标，同一行的小问由代码合并为一行（`&emsp;&emsp;`），不交给模型判断；
  已通过检验的题续跑时跳过；填空横线统一规范，避免模型复读失控。
- 切片：存在且尺寸正常。
- 解答：定稿非空、速查非空（缺失时按定稿补生成）、评审状态。
扫描件的题干一律由大模型对照原图转写，不使用本地 OCR 的零碎文字。

## 已知限制

- 双栏排版的书、没有“习题”类标题的书尚未覆盖；题号为字母或罗马数字的不支持。
- 两题之间若没有任何空白（如下一题求和号上限紧贴上一题），这一小块可能被切进上一题；转写时会提示模型忽略相邻题的零星符号。
- 检验会逐符号核对公式，但仍是模型判断，不能保证 100% 无误；网页上可一键“重新识别并重解”。

- 整本扫描书 OCR 在普通 CPU 上要几十分钟，缓存可续跑。
- 评审是模型自评，不能替代人工抽查；有书末答案时可作为后续的外部校验依据。
